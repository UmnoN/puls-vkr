# ПУЛЬС — сервис приоритизации сделок (прототип для ВКР)

## Структура
```
puls_service/
  core/
    db.py               — подключение к БД + описание таблиц (Postgres/SQLite), схема v2
    feature_logic.py     — общие константы (стадии, эвристика)
    logging_service.py   — логирование по сервисам
  services/
    ingestion_service.py          — [v1, устарел] загрузка первичной выгрузки (777 сделок)
    feature_scoring_service.py     — [v1, устарел] признаки/скоринг на первичной выгрузке
    ingestion_service_v2.py        — загрузка полной выгрузки ПУЛЬС (764 сделки + 399 лидов)
    feature_scoring_service_v2.py  — признаки, эвристика, GBM-модель, модель конверсии лид→сделка
  streamlit_app.py       — интерфейс для менеджера/руководителя (4 вкладки, включая лиды)
  schema.sql             — DDL-схема для настоящего Postgres (актуальна под v2)
```

Файлы v1 оставлены для истории разработки (см. главы 2-3 пояснительной
записки — переход на v2 и его обоснование описаны там же). Для реальной
эксплуатации использовать только `_v2` сервисы.

## Установка
```bash
pip install -r requirements.txt
```

## Запуск (локально, на SQLite — без установки Postgres)
```bash
cd puls_service
python -m services.ingestion_service_v2 сделки_v2.csv лиды_v2.csv
python -m services.feature_scoring_service_v2
streamlit run streamlit_app.py
```

Файлы `сделки_v2.csv` и `лиды_v2.csv` — очищенные от персональных данных
(company_name, ИНН, ФИО менеджера удалены) версии выгрузки ПУЛЬС
(`bauman_dataset_20260730.xlsx`, листы "Сделки" и "Лиды").

По умолчанию используется локальный файл `puls_local.db` (SQLite) —
удобно для разработки и для защиты ВКР без разворачивания сервера.

## Переключение на настоящий Postgres
Задать переменную окружения перед запуском — код менять не нужно:
```bash
export DATABASE_URL="postgresql+psycopg2://user:password@host:5432/puls"
```

## Логика (кратко, v2)
- **Ingestion v2** — загрузка сделок и лидов, объединение обозначений
  пустого Холдинга, разметка `is_resolved` (завершена сделка/лид или нет).
- **Feature & scoring v2** — эвристика по стадии (только новые сделки),
  weighted_potential, reactivation_score (провальные сделки, окно 365 дней
  на реальном поле `days_since_last_contact`), ML-модель прогноза закрытия
  сделки (Gradient Boosting, обучена ТОЛЬКО на 274 завершённых новых
  сделках — активные получают инференс-прогноз, не участвуют в обучении),
  вторая модель — конверсия лида в сделку (логрег, обучена на решённых
  лидах, аналогичный inference для нерешённых).
- Все шаги пишут в `service_logs` — видно во вкладке "Логи сервисов".
- Streamlit: 4 вкладки — приоритет активных сделок, реактивация провальных,
  лиды (по вероятности конверсии), логи сервисов.
